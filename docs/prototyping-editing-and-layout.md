# 组件编辑、对齐与吸附评估

本轮围绕“插入现成模板、修改内部组件、排列重复内容”这条原型绘制流程，改进现有编辑器，不改变项目文件格式。

## 用户问题与落地行为

| 操作场景 | 原先的问题 | 改进后的行为 |
| --- | --- | --- |
| 修改模板内部组件 | 非文字组件双击仍选回整个组合；拖动子组件又会选回组合 | 双击选中内部组件；进入后可继续选择、移动同级组件；保留整体层级 |
| 从面板编辑模板 | 组合入口主要是“打散” | 增加“编辑内部组件”列表和“返回父容器”，直接使用所选子组件原有的内容、状态和样式编辑控件 |
| 对齐不同容器里的组件 | 直接比较局部坐标，视觉上无法对齐 | 用画布坐标计算，再转换为各自父容器内坐标写回；同时选中父子时只移动父级 |
| 单个组件居中 | 根级组件会移向不可见的 1440 × 900 默认画板 | 有父容器时对齐父容器；无限画布上的单选禁用对齐并说明原因 |
| 排列多个不同宽高组件 | 分布逐项累加取整，间距可能产生累计偏差 | 保持两端位置，按边到边距离均分；不累计舍入误差 |
| 设置卡片或按钮间距 | 只能自动分布，不能直接设定统一数值 | 选择至少两个未锁定组件，输入间距，再设置水平或垂直间距；固定最左或最上组件 |
| 拖动模板或多个组合 | 扁平列表残留被移动组件的子级，导致吸附自身 | 将被移动组件及其全部后代排除出吸附目标 |
| 在模板中拖动、缩放组件 | 吸附目标、活动组件及参考线使用不同坐标系 | 矩形移动和缩放统一在画布坐标计算，保留本地存储坐标 |
| 手动排一行或一列 | 没有相等间距的吸附反馈 | 邻近边线未命中时，提供延续等间距或居中插入的吸附，并显示两段间距数值 |
| 精细拖动 | 中心吸附范围较大，缩放后手感不一致 | 矩形边线、中心线使用 6 个屏幕像素阈值；Alt 临时关闭；数值标注保持屏幕字号 |
| 锁定内容参与排列 | 分布会静默忽略锁定项 | 存在锁定项（包括父级锁定）时禁用间距和分布；对齐仍可参照锁定项但不会移动它 |

新增界面沿用 Space Grotesk、Space Mono 与现有明暗主题。辅助线与间距标注使用中性色，移除标注阴影。

## 参考依据与选择

- [Figma：位置、对齐与分布](https://help.figma.com/hc/en-us/articles/360039956914-Adjust-alignment-rotation-position-and-dimensions)：等距分布保留两端组件位置，支持调整组件间距。本轮沿用项目已有的选区边界作为多选对齐参照。
- [Axure：组织组件](https://docs.axure.com/axure-rp/reference/organizing-widgets/)：附近组件的边缘、中线与距离反馈支持快速排版；组合让组件仍可作为整体管理。Axure 的首选组件对齐参照与 Figma 风格的选区参照不同，本轮不混用两套默认规则。

## 验收方式

- 单元回归直接加载生产 TypeScript，覆盖坐标转换、父子排除、隐藏/锁定继承、不同尺寸等距排列、指定间距与撤销、多个缩放级别、等距吸附，以及所有真实模板的子组件结构。
- 类型检查：`pnpm typecheck`。
- 全部测试：`pnpm test`。
- 生产静态构建：`BLUEPEN_BUILD_DIR=.next/prototyping-final NEXT_EXPORT=true pnpm --filter app exec next build --webpack`。

## 本次验证结果

- 全部 74 项测试通过，其中本轮新增 14 项；编辑器与应用类型检查通过。
- 最终源码生产构建通过，使用静态产物进行浏览器验收。
- 登录模板：内部按钮改为“进入原型工作台”，返回组合后仍有 10 个图层；重载后文案保留。
- 子组件拖动：局部坐标 `(24, 92)` → `(44, 112)`，一次撤销恢复 `(24, 92)`，父模板不动。
- 垂直间距：输入 24 px 后第二项 Y 从 164 变为 172；一次撤销恢复 164。
- 等距吸附：三个不同宽度矩形，拖动第三项至原始 X=283 后吸附到 X=280，显示两段 20 px 标注；撤销恢复 X=330。
- 深浅主题均检查；浏览器控制台错误和警告为 0。

## 边界与后续评估

本轮针对常规未旋转矩形组件和组合的原型排版。旋转祖先的变换矩阵、连接线端点吸附、网格吸附设置、二维自动整理、自动布局约束不在本轮实现范围；不能把当前坐标修正视为这些场景的完整支持。未进行原生安装包或 Windows 实机验证。

# Web 与 Agent 组件库审计

## 结论

当前组件库“覆盖面很大”，但用户找组件的路径仍然按实现类型组织，而不是按原型任务组织。Web 库 65 个条目、Agent 库 27 个条目，足以覆盖常见场景；继续增加同类组件的收益低于重排、合并和补齐状态。建议把库改成“先选页面/区块，再选组件，再用状态变体”的三层结构，并让右侧面板按组件语义显示属性。

本审计按原型工作流评估：用户通常先搭页面骨架，再填内容，再补交互状态，最后调视觉细节。分类、默认排序和面板都应服务这条路径。

## 当前结构的主要问题

### 1. 库的排序与起手动作相反

- Web 当前顺序是“导航 → 表单 → 展示 → 反馈 → 模板”。真实起手通常是先拖入页面模板/布局，再放导航、内容区和反馈。因此模板应置顶，且应按“页面模板 / 页面区块 / 组件 / 状态”分层。
- Agent 当前顺序是“基础图元 → 框架容器 → 结构与数据 → 核心交互 → 场景模板”。Agent 原型通常先选首页、聊天态或分栏工作台，再调整 prompt、消息和执行流；完整模板放最后会迫使用户先拼装底层结构。
- `left-sidebar.tsx` 只有模式和分类折叠，没有“最近使用 / 收藏 / 推荐起手模板 / 当前页面可用组件”入口，导致 27 或 65 个条目都要靠搜索记忆。

### 2. 重复条目增加选择成本

- `button` 同时出现在基础库、Web 表单和 Agent 基础图元；`table`、`file-list` 也跨库重复。它们的差异主要是预置内容或视觉变体，应合并为一个组件，通过“场景预设”或变体选择解决。
- `web-button` 与 `button` 的语义高度重叠；`web-message`、`web-notification`、`web-tips` 也可统一为“反馈/浮层”组件，用 placement、status、触发方式区分。
- Web 表单 21 项过细：`select`、`cascader`、`tree-select`、`auto-complete`、`tag-input` 可归入“选择与输入”，日期/时间归入“时间”，上传/transfer 归入“资源”。用户需要的是任务能力，不是组件实现名。
- Agent 同时提供 `agent-client-home/chat/split` 和多个 `*-layout`。前者是完整客户端状态，后者是页面模板，命名和层级不清。建议保留一套“客户端壳 + 状态变体”，模板只保留可直接落地的业务页面。

### 3. 存在与设计规范冲突的条目

`web-skeleton` 属于 Web 反馈，但项目设计规范明确禁止 skeleton loading。应删除，或改成静态“加载中状态”组件（文本、分段进度、工具步骤）。`web-message` 若实现为 toast，也与“禁止 Toast，使用行内状态”冲突，应在库里改名为“行内反馈”并限制展示方式。

### 4. Agent 工作流的关键状态不完整

现有 Agent 核心交互覆盖 prompt、用户消息、思考流、工具步骤、附件和工件标签，但缺少原型中决定产品行为的状态：

- 权限确认 / 工具调用前批准
- 工具调用失败、重试、取消、超时
- 流式输出中的停止生成、继续生成、部分结果
- 引用来源、引用展开、来源失效
- 结构化结果（表格、代码、图表）与“打开工件”动作
- 空会话、网络断开、额度不足、模型不可用
- 多轮消息中的分支、重新生成、编辑后重发

这些应作为同一组件的状态变体，避免再创建大量只差一张状态图的条目。

## 建议的库结构与默认排序

### Web

1. **页面起手**：管理后台、Dashboard、CRUD、表单页、登录、设置、文件管理、定价/FAQ。
2. **页面区块**：页头、筛选条、统计卡、表格区、详情区、空状态、侧栏/抽屉区。
3. **导航**：顶部导航、侧边菜单、面包屑、Tabs、分段、步骤、分页。
4. **输入与选择**：输入、数字、文本域、选择、联想、标签、日期时间、开关、滑块、上传、颜色。
5. **数据展示**：表格、列表、文件列表、描述列表、树、看板、日历、时间线、图表、卡片。
6. **反馈与浮层**：行内 alert、确认、modal、drawer、popover、空状态、错误/成功/警告状态。

默认首屏只展开“页面起手”和“页面区块”，其余折叠。每个条目显示用途标签，例如“后台 / 数据密集 / 表单”，帮助用户按目标选择。

### Agent

1. **客户端起手**：通用首页、聊天执行态、分栏工作台、知识库、员工/技能市场。
2. **会话骨架**：导航侧栏、会话列表、项目树、会话头、工件标签。
3. **输入与上下文**：Prompt 输入、模型/权限、附件、建议词、上下文范围。
4. **执行流**：用户消息、流式回答、思考状态、工具步骤、批准、失败/重试、引用。
5. **结果与数据**：文件列表、目录树、控制台表格、代码/表格/图表结果、工件预览。
6. **通用图元**：文字、矩形、线、图片、按钮、徽标。默认折叠，只有需要精修时使用。

Agent 的“完整客户端”应是模板；“首页 / 聊天 / 分栏”应作为同一 `agent-client` 的状态变体，减少重复入口。

## 编辑面板重构建议

### 面板应从“属性全集”改为“任务优先的四层

1. **内容**：文本、列表、列、标题、占位符、数据样例。放在最上方，输入后立即能看到结果。
2. **状态与行为**：默认/悬停/禁用/加载/成功/警告/错误；打开态、当前项、触发方式；Agent 的批准、重试、流式、引用等状态。
3. **布局**：尺寸、内外间距、对齐、方向、子项间距、响应式约束。组件模板应优先暴露语义布局，而不是只暴露 x/y/width/height。
4. **视觉与高级**：填充、描边、圆角、字体、透明度、旋转、CSS Inspect。默认折叠，避免每个组件一上来都看到大量绘图属性。

### 目前右侧面板的具体改进点

- `right-panel.tsx` 用多个巨型 `Set`（`TEXT_TYPES`、`STROKE_SUPPORTED_TYPES`、`FILL_SUPPORTED_TYPES`、`RADIUS_SUPPORTED_TYPES`）维护能力，新增组件容易漏配。应把组件元数据与编辑 schema 放在库定义旁边，由 schema 驱动支持哪些字段。
- Web 专属编辑区已经较完整，但 Agent 只有 prompt 和少数工具条的专属编辑项；应为 Agent 状态组件补齐“状态、动作、数据结构、可见性”四类字段。
- 同一语义的属性命名不统一：`text`、`label`、`title`、`placeholder`、`items1/items2` 并存。应提供规范化 schema，渲染层做兼容迁移。
- 菜单、步骤、Tabs、列表目前使用逗号字符串或 JSON 字符串编辑。应改为可增删、排序、复制的结构化行编辑器，并保留高级 JSON/文本入口。
- 多选时只批量显示通用几何属性；应显示“共同属性”和“混合值”，允许批量修改状态和内容字段。
- 复制 CSS 的动作通过 toast 回馈，与项目规范冲突；改为面板内 `[COPIED]` 行内状态。
- 面板应显示组件来源（模板/组件/基础图元）、适用场景和当前状态，帮助用户判断是否选对组件。

## 建议的删减、合并与新增清单

### 先合并

- `button`、`button-primary`、`web-button` → `button` + variant。
- `table`、`web-table`、`file-list` → `data-view`，用 viewType 区分 table/list/file。
- `web-select`、`web-cascader`、`web-tree-select`、`web-auto-complete`、`web-tag-input` → `choice-input` + mode。
- `web-modal`、`web-drawer`、`web-popconfirm`、`web-notification`、`web-tips`、`web-message` → `feedback-overlay` + kind/placement。
- Agent 的 `agent-client-*` 与 `agent-*-layout` → `agent-client` 壳 + preset/state。

### 先删除或降级

- 删除 `web-skeleton`。
- 删除库中的 toast 语义，统一为行内反馈。
- 将极少独立使用的 `web-pricing-table`、`web-faq-section` 作为页面区块变体，不占用一级组件入口。

### 优先新增

- Web：搜索结果/筛选无结果、表单校验组、批量操作条、响应式栅格/分栏、权限/角色矩阵、导入导出状态。
- Agent：批准卡、失败/重试卡、停止/继续生成、引用来源、结构化结果、模型不可用、额度/权限提示、分支消息。

## 落地顺序

1. 先改分类、排序和折叠默认值，不改变渲染器，验证用户能否在三步内找到页面起手组件。
2. 建立组件元数据/schema，驱动左侧标签和右侧面板能力，逐步移除硬编码 Set。
3. 合并重复 type，增加旧 type 到新 type 的迁移映射，保证已有页面可打开。
4. 增加 Agent 缺失状态与 Web 常用业务区块。
5. 最后再做视觉预设和默认 props 调整，避免把结构问题误当成样式问题。

## 验收标准

- 新用户从空画布开始，Web/Agent 都能在 3 次点击内进入一个可用页面起手模板。
- 常见按钮、表格、选择器只出现一个主入口，变体在面板中选择。
- 任一库条目都能在面板看到“内容、状态/行为、布局、视觉”中至少前三类适用字段；不适用字段不显示。
- Agent 原型可覆盖成功、流式、批准、失败重试、引用和结构化结果六类关键状态。
- 旧项目中的重复 type 经过迁移后视觉与可编辑性不回退。
